# Contributing

See [README.md](README.md) for installation and configuration, or [README.zh-CN.md](README.zh-CN.md) for Chinese instructions. Use JDK 17 and Python 3.8+. No existing Minecraft installation or system Gradle is required.

## Build and checks

Windows:

```powershell
.\gradlew.bat build compileIntegrationJava productionMixinSmoke
```

Linux / macOS:

```sh
./gradlew build compileIntegrationJava productionMixinSmoke
```

The first build needs network access. Wrapper caches default to `.gradle-home`; explicit Gradle user-home settings are respected. Select Python with `-PpythonExecutable=/path/to/python3` or `PYTHON` if needed.

`build` covers capacity, SavedData, configuration, localization, Origins failure handling, perimeter geometry, linkage, and artifact checks. `compileIntegrationJava` compiles the gameplay fixtures; it does not run them. `productionMixinSmoke` loads the production jar and Forge SRG classes in an isolated headless process, checks transformed hooks and their actual branches, and never creates a world.

Commit source, resources, build files, tests, and user-facing documentation. Do not commit caches, runtime configurations, worlds, logs, third-party test jars, local references, or development notes. Keep the Wrapper jar and test structure NBT. Refmaps are generated by the Mixin annotation processor; production remapping belongs to ForgeGradle.

## Targeted gameplay testing

Use a new test world name for creation scenarios and the same existing name for restart scenarios:

```powershell
.\gradlew.bat runClient -PclientRegression=structure -PtestWorld=selector-structure-test
.\gradlew.bat runClient -PclientRegression=restart -PtestWorld=selector-structure-test
.\gradlew.bat runClient -PclientRegression=vanilla -PtestWorld=selector-vanilla-test
.\gradlew.bat runClient -PclientRegression=vanillaRestart -PtestWorld=selector-vanilla-test
.\gradlew.bat runClient -PclientRegression=fixtures -PtestWorld=selector-world-tests
```

The client regression harness uses the real UI/network flow and reports `CLIENT_REGRESSION PASS/FAIL` before saving and exiting. `fixtures` runs eight world GameTests on the integrated server. `runGameTestServer` uses `run/gametest`; dedicated runs require the user's EULA agreement.

Optional Origins testing requires supplying your own Origins and Caelus jars:

```powershell
python tools/prepare_origins_fixture.py "path/to/origins.jar" "path/to/caelus.jar"
.\gradlew.bat runClient -PoriginsFixture -PclientRegression=origins -PtestWorld=selector-origins-test
.\gradlew.bat runClient -PoriginsFixture -PclientRegression=originsRestart -PtestWorld=selector-origins-test
.\gradlew.bat runClient -PoriginsFixture -PclientRegression=originsBroken -PtestWorld=selector-origins-broken-test
```

Dependencies are unpacked only into ignored `test-mods` and remapped by ForgeGradle. Use test worlds only. `holdingRecoveryFixture` modifies a closed project test world's player NBT after acquiring its lock and creating a local backup; never use it on real saves.

For changes involving world generation, networking, or GUI behavior, choose relevant gameplay cases and record what remains untested. Full dedicated-server worlds and real two-client multiplayer still need regression coverage.

## Implementation and pull requests

Preserve holding, deferred vanilla spawn, independent player sessions, existing save compatibility, real-size collision checks, and destination acknowledgment. Commit world state and capacity changes on the server thread. Optional compatibility must fail softly per player; discovery and chunk preparation must remain bounded.

Keep changes focused. A PR should state the concrete problem, resulting behavior, checks run, and limitations. Avoid unnecessary package renaming or rewrites of working lifecycle code.

Contributions are provided under AGPL-3.0-only. Verify third-party licenses before incorporating code and retain the appropriate notices. Local audit and development notes are not part of the public documentation.
